SCM 是亿企工场的供应链业务子仓，在主平台中位于 `modules/art-supabase-scm`。本仓维护供应链页面、业务 API、领域类型和规则；认证、租户、菜单、权限、布局、公共组件与 Supabase 公共客户端由主平台提供。

## 当前能力

| 领域     | 业务内容                                                                           |
| -------- | ---------------------------------------------------------------------------------- |
| 销售报价 | 费用定义、报价项分类、销售报价单、项目报价汇总与关联业务查询                       |
| 报价转换 | 按明细和数量生成物料、销售合同、销售订单、采购申请/订单、报价 BOM 与 MES 工单      |
| 销售管理 | 销售合同、销售订单、发货通知、发货装车、装车出库与分批数量跟踪                     |
| 采购管理 | 采购合同、采购申请、采购订单、收料通知、来源参选、合同定价与单据打印               |
| 业务协同 | MDM 物料及多单位换算、WMS 采购入库与销售出库、流程中心审批、业务引用与库存流水追溯 |

菜单和操作按当前租户的授权显示。转单还需满足来源单据状态、目标权限、项目、供应商及剩余数量等业务条件。

## 近期完善

- 报价按来源明细分批转换，展示实际已转和剩余数量；项目报价工作区汇总合同、采购申请/订单、实时库存与库存流水。
- 采购单据支持单据/明细两种工作方式、批量操作、采购员维护、来源选取、历史采购价格参照及打印。合同定价与申请、报价来源分别保留，避免覆盖来源关系。
- 采购订单与收料通知可按来源及剩余数量下推 WMS 采购入库草稿；订单展示送货、入库、退货及未入库进度。
- 装车出库按已确认装车明细办理，支持库存批次、序列号、分批及批量出库，关联实际库存流水；失败重试保留请求身份。
- 单据表单持续统一到 `ArtForm` 配置，复用物料参选、附件、详情、加载和失败重试能力；删除统一使用 `MasterDataDeleteGuard` 检查业务引用。

## 跨模块流程与边界

```text
MDM 物料 / 单位 / 仓库 / 项目
  ├─ 销售报价 → 合同 → 订单 → 发货通知 → 装车 → WMS 销售出库
  ├─ 采购申请 / 合同 → 采购订单 → 收料通知 → WMS 采购入库
  └─ 报价明细 → 物料 / 报价 BOM / MES 工单
```

销售报价、合同和订单接入平台审批中心。审批中的单据受状态保护；符合条件且有权限时可以撤回，审批回调负责更新业务状态。金额、来源关系、转单额度、库存和状态变化由服务端复核，库存结果以 WMS 过账为准。

采购入库、退货及相关仓储作业归属 WMS，SCM 保留来源单据与下推入口。采购申请的“生成计划”到 MES 生产计划链路尚未接通；WMS 出库与 TMS 承运交接也需独立契约，不能把出库完成等同于运输交接完成。

## 本地开发

要求 Node.js `>= 22.13.0`、pnpm `11.28.2`，以 `package.json` 为准。

```powershell
pnpm install
pnpm dev
```

默认地址为 `http://localhost:3021/`。在主仓工作区中，先按主仓 README 安装依赖、配置后端并初始化子模块；本仓 Vite 配置会定位主平台运行时。独立克隆时通过已声明的 `art-supabase-pro` 依赖提供公共运行时，也可用 `ART_SUPABASE_PLATFORM_ROOT` 指向主仓。前端仅配置公开客户端凭证，服务端密钥不得进入 Vite 环境变量。

```powershell
pnpm typecheck
pnpm check
pnpm build
pnpm preview
```

`check` 包含模块边界审计、UI 审计、类型检查、ESLint 和本仓单元测试。生产构建输出到受版本控制的 `docs/`，公共路径默认 `/art-supabase-scm/`。主平台集成构建和发布方式见主仓 README。

## 权限与维护

- 普通用户仅操作本人租户内已授权的业务数据。平台超级管理员支持全部租户或指定租户工作区；已有单据及其子记录保持明确的租户归属。
- 新增、编辑、审批、下推、出库与删除分别按业务权限控制，跨模块操作还要校验目标模块权限。前端可见性不能代替服务端授权。
- 删除前展示引用记录；引用检查失败时阻止删除并允许重试，服务端并发拒绝后重新检查引用。
- 销售合同与采购合同的附件存于单据 `details.contract_attachments`，每项记录名称、资源 URL、格式和字节数。合同保存时数据库核对 `sys_attachment` 的同租户资源并锁定资源行；资源仍被合同时禁止从附件管理删除。转成其他单据时移除合同附件字段。回归脚本见主仓 `tests/integration/scm-contract-attachments.sql`。
- 通用前端能力归主仓，本仓不复制公共实现，也不直接导入其他业务子仓的前端源码。
- 先提交并推送本仓，再更新主仓的子模块指针。中文与英文 README 同步维护；详细行为与回归用例以当前源码、主仓测试及[使用文档](https://art-si.github.io/art-supabase-doc/modules/scm)为准。
